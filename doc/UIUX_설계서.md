# safeDoc UI/UX 설계서

- **상태**: 구현 완료 (2026-11-24 재설계)
- **구현 위치**: `index.html`, `src/style.css`, `src/main.js`, `src/ui/`
- **대상 환경**: 업무용 PC 1366×768 이상. 1024px 이하와 모바일 폭에서도 가로 스크롤 없이 사용할 수 있다.

## 1. 설계 원칙

safeDoc은 사람이 후보를 하나씩 판단하는 **반복 검토 도구**다. 장식보다 정보 밀도, 판단 속도, 오조작 방지를 우선한다.

1. **색은 상태만 말한다.** 미확인(주황), 처리(청록), 제외(회색), 민감·위험(빨강). 개인정보 유형은 색이 아니라 텍스트로 구분한다.
2. **주요 행동은 항상 같은 자리에 있다.** 모든 단계에서 오른쪽 아래의 하단 고정 바가 다음 행동이다.
3. **비활성 버튼은 이유를 말하지 못한다.** 미확인 후보가 남으면 버튼 문구가 `미확인 N건 확인하기`로 바뀌어 지금 할 일을 직접 안내한다.
4. **판단은 되돌릴 수 있고 위험한 일괄 동작은 한 번 더 묻는다.** `Ctrl+Z`로 되돌리고, 여러 건을 한꺼번에 제외하면(원문이 결과에 남는다) 확인 창을 띄운다.
5. **외부 자원이 없다.** 글꼴·아이콘·스크립트를 모두 번들하거나 시스템 글꼴을 쓴다(폐쇄망, CSP).

## 2. 정보 구조

```
상단 메뉴 ─ 비식별 처리 │ 관리                          [새 작업] [⚙ 설정 팝업]
작업 단계 ─ ① 문서 준비 ② 규칙 기반 탐지 ③ AI 탐지 ④ 개인정보 검토 ⑤ 처리 확인 ⑥ 완료      [이 PC에서만 처리 · AI 상태]
```

- 상단 메뉴는 유지하고, 그 아래 높이 60px(낮은 화면 52px)의 작업 단계 바에 진행 단계와 AI 상태를 함께 둔다. 단계 원은 28px, 단계 사이 연결선은 화면 폭에 따라 16~56px이다. 이전 구조의 세로 단계 표시와 페이지 제목 영역은 없앴다.
- **관리**는 `원본 복원 / 처리 정책 / 사용자 규칙` 세 항목의 화면이다. 작업 도중에도 오가며 쓰는 것들을 한곳에 모았다.
- **설정**은 메뉴가 아니라 오른쪽 위의 톱니바퀴 아이콘 버튼이다. 누르면 팝업이 열리고 `AI 엔진`(상태 확인·사용 여부·고급 설정)과 `기본값 복원`만 담는다. 자주 바꾸지 않지만 어느 화면에서나 닿아야 하는 항목이라 화면 전환 없이 팝업으로 둔다. 아이콘만 있으므로 이름은 `aria-label="설정"`으로 제공한다.
- 팝업은 바깥 클릭·`Esc`·메뉴 전환·포커스 이탈로 닫힌다. `Esc`로 닫으면 포커스가 톱니바퀴로 돌아가고, 팝업을 조작하는 동안에는 검토 단축키가 동작하지 않는다.

## 3. 화면별 설계

| 단계 | 구성 |
| :--- | :--- |
| 문서 준비 | 파일 끌어놓기 영역과 처리 기준표(형식·용량·제외 대상·처리 위치·탐지 방식). 홍보성 문구와 접힌 설명을 없앴다. |
| 규칙 기반 탐지 | 진행 막대와 4단계 체크리스트(문서 열기·텍스트 추출·규칙 탐지·화면 준비). |
| AI 탐지 | 규칙 결과가 담긴 검토 화면이 **읽기 전용**으로 열리고 위에 AI 진행 배너가 뜬다. 끝나면 같은 화면이 4단계로 바뀌며 판단할 수 있게 된다(아래 참고). |
| 개인정보 검토 | 왼쪽 문서, 오른쪽 후보 표와 상세 영역의 2분할 카드. 화면 가장자리와 두 카드 사이에 16~24px 여백을 둔다. 페이지 스크롤 없이 화면 높이에 맞추고 스크롤은 문서와 표 안에서만 일어난다. |
| 처리 확인 | 처리 대상·제외·미확인 건수, 처리방식별·유형별 건수, 대응표 생성 선택(기본 `생성하지 않음`). |
| 완료 | 결과 문서 다운로드가 유일한 주요 버튼. 변경 항목 표, 처리 내역, 보고서·대응표는 보조 영역. `나란히 비교`는 처리 전·후 문서를 함께 스크롤한다(아래 참고). |
| 관리 › 원본 복원 | 두 파일 선택 → 일치 여부와 복원 가능·불가 건수 확인 → 실행. |
| 관리 › 처리 정책 | 유형별 기본 처리방식과 적용 예시 표. |
| 관리 › 사용자 규칙 | 규칙 이름·정규표현식 입력과 등록된 규칙 목록. |

### 나란히 비교의 동시 스크롤

어느 쪽을 굴려도(휠·스크롤바·키보드) 다른 쪽이 같은 위치로 따라간다. 처리 후 문서는 치환 문구 길이에 따라 줄바꿈이 달라지므로 스크롤 비율만 맞추면 아래로 갈수록 어긋난다. 그래서 양쪽에 같은 순서로 있는 강조 항목을 기준점으로 삼아 기준점 사이를 선형 보간한다(`src/ui/syncScroll.js`). 강조 항목의 개수가 달라 기준점을 만들 수 없으면 스크롤 비율로 맞춘다. 두 영역은 키보드로 포커스를 받아 스크롤할 수 있다.

### AI 탐지 단계(3단계)와 읽기 전용

AI 탐지는 규칙 결과를 보여 준 뒤 이어서 돈다. 이 동안 판단을 허용하면 결과가 AI의 새 후보와 뒤섞이므로, 검토 화면을 읽기 전용으로 잠그고 단계 바를 `③ AI 탐지`로 표시한다.

- 허용: 표 훑어보기·후보 선택(문서 위치 이동), 필터·정렬, 키보드 `J`/`K` 이동. 판단(처리/제외), 일괄 동작, 유형·처리방식 변경, 되돌리기, 직접 추가는 잠긴다(`inert`와 입력 차단).
- 화면 전체가 옅게 보이고(투명도·채도 낮춤) 하단의 `처리 확인` 버튼은 눌리지 않는다.
- 끝나면 `④ 개인정보 검토`로 바뀌고 잠금이 풀린다. AI를 쓰지 않았거나 중단·사용 불가·오류로 끝까지 수행하지 못했으면 3단계 원이 `–`(건너뜀)로 표시된다.
- `AI 탐지 중단`으로 언제든 끝낼 수 있다. 응답이 잘려 끝내 읽지 못한 구간이 있으면 `AI 미완료`로 알리고 사유와 검사한 구간 수를 함께 보여 준다.

### 개인정보 검토 화면

- **AI 진행 배너**: AI 탐지가 진행되는 동안에만 패널 위에 나타난다. 회전하는 표시, 움직이는 줄무늬 진행 막대, `추가 탐지 n/m · k건 발견`, `AI 탐지 중단` 버튼을 담고 배너 테두리가 맥박처럼 깜박인다. 단계 바에서는 현재 단계 원 둘레에 고리가 돌고 `AI ···` 표시가 붙으며, 새로 찾은 후보 행은 잠깐 강조된다. 동작 줄임 설정에서는 움직임이 꺼지고 문구와 진행 막대 길이만 남는다. 낮은 화면(높이 800px 이하)에서는 배너의 보조 문구를 숨겨 높이를 줄인다.
- **후보 표**는 한 줄 36px 행으로 `상태 · 개인정보 · 유형 · 문맥 · 판단(처리/제외)`을 보여 준다. 열 머리글은 스크롤해도 고정된다. 1440×900에서 13건, 1366×768에서 9건이 한 화면에 들어온다(AI 배너가 있는 동안은 2건 적다).
- **상태 필터**(전체·미확인·AI 발견·오탐 의심·제외·수동)가 탭으로 위에 있고, 유형 필터와 정렬은 그 아래 도구줄에 있다. 표시된 후보에 대한 일괄 처리·제외·처리방식 변경도 같은 줄이다.
- **상세 영역**은 선택한 후보의 유형·처리방식 변경, 신뢰도·탐지 방식, 결과 예시, 같은 값 일괄 판단을 담는다. 처리방식 선택상자를 모든 행에 반복하지 않는다.
- **문서 강조**는 후보 상태와 같은 색을 쓴다. 후보를 선택하면 문서가 해당 위치로 이동하고, 판단하면 강조 색이 즉시 바뀐다.
- **직접 추가**: 문서를 드래그하면 선택 영역 바로 옆에 팝오버가 떠서 유형을 고르고 추가한다. 검색 일괄 지정은 문서 위 도구줄에 있다.
- **키보드**: `J`/`K` 이동, `I` 처리, `X` 제외(판단 후 다음 미확인으로 자동 이동), `Enter` 상세 편집, `1`~`4` 처리방식, `Ctrl+Z` 되돌리기. 문서 본문에 포커스가 있으면 방향키는 스크롤이다.

## 4. 디자인 시스템

- **간격** 4px 배수. **글자** 12·13·14·16·20·24px 단계만 사용. 본문 14px, 문서 본문 14.5px.
- **색 토큰**은 `:root`에 정의하고 `prefers-color-scheme: dark`에서 재정의한다. 본문·보조 텍스트·상태색 조합의 대비는 라이트·다크 모두 4.5:1 이상으로 측정했다.
- **상단 메뉴**는 짙은 남색 띠, 현재 메뉴는 하늘색 밑줄. 로고 이미지의 여백은 잘라 내어 표시한다.
- **버튼**은 `primary`(다음 단계·실행·다운로드), 기본(보조), `ghost`(텍스트형), `danger-outline`(대응표) 네 종류만 쓴다.
- **포커스**는 2px 외곽선 링으로 모든 조작 요소에 표시한다. `prefers-reduced-motion`을 따른다.
- **알림**은 오른쪽 위 토스트(3.5초)와 화면 안 경고 띠로 나눈다. 보조기술용 알림은 별도의 live region으로 보낸다.

## 5. 접근성

- 건너뛰기 링크, 단일 `h1`, 단계 표시의 `aria-current`, 필터의 `aria-pressed`.
- 후보 표는 `role="table"`로 노출하고 행마다 판단 버튼 그룹에 `값 (유형) 검토 결정` 이름을 둔다.
- 문서 본문 강조는 `role="button"`이며 Enter·Space로 후보로 이동한다.
- 모든 클릭 대상은 높이 28px 이상(기본 버튼 34px).
- AI 결과가 비동기로 도착하면 live region으로 알린다.

## 6. 반응형

| 폭 | 변화 |
| :--- | :--- |
| 1500px 이하 | 하단 바의 단축키 안내를 숨긴다. |
| 1280px 이하 | 후보 표 열 폭을 줄이고 보조 문구를 숨긴다. |
| 1024px 이하 | 검토 화면이 문서·후보 표 세로 배치가 되고 하단 바는 화면 아래에 고정된다. |
| 720px 이하 | 상단 메뉴가 두 줄이 되고(첫 줄에 로고·새 작업·톱니바퀴), 관리의 하위 항목이 가로 탭이 된다. 설정 팝업은 화면 폭에 맞춰 줄어든다. |

## 7. 검증 기록 (2026-11-24)

1920×1080, 1440×900, 1366×768, 1024×768, 375×812에서 가로 넘침이 없음을 확인했고, 검토→처리 확인→실행→결과 내려받기→복원의 전체 흐름을 브라우저에서 끝까지 실행했다. 나란히 비교의 동시 스크롤은 실제 휠 입력으로, AI 탐지는 실제 Ollama로 확인했다. 단위 시험 239개와 프로덕션 빌드가 통과한다. 사용자 인터뷰와 사용성 시험은 수행하지 않았다.

README의 화면 캡처는 결과가 매번 같도록 AI 응답을 고정한 모의 엔진으로 촬영했다(`AI 발견` 항목은 설명용 예시).
